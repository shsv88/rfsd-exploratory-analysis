EDA открытой базы бухгалтерской отчётности российских фирм
[RFSD](https://github.com/irlcode/RFSD) средствами Pandas / PyArrow / Seaborn.

**Репозиторий:** https://github.com/shsv88/rfsd-exploratory-analysis

## 2. Как выполнено ограничение «20 колонок × 1000 строк»

Датасет не скачивается вообще: pyarrow запрашивает по HTTP только те диапазоны байт, где лежат
нужные колонки нужных row-групп. Использованы три приёма:

1. **Одна партиция года** — читается только `year=2023`.
2. **Column pruning** — из ~210 колонок читаются ровно 20. Parquet колоночный, поэтому остальные
   ~190 колонок не передаются по сети и не попадают в память.
3. **Streaming + резервуарная выборка** — файл обрабатывается батчами через
   `ParquetFile.iter_batches()`, в памяти одновременно находятся только текущий батч и 1000 строк.

Авторы RFSD предупреждают, что внутри года данные не перемешаны, поэтому «первые 1000 строк» дали
бы смещённую выборку. Каждой строке приписывается случайный ключ `U(0, 1)`, в резервуаре остаются
1000 строк с наименьшими ключами — это равносильно равновероятной выборке при константном
потреблении памяти.

Режимом чтения управляют три константы в разделе 1.2 ноутбука:

| Константа | По умолчанию | Что делает |
|---|---|---|
| `STREAM_OVER_NETWORK` | `True` | чтение по сети батчами, файл не скачивается. `False` — один раз положить файл партиции (~0.5 ГБ из 6.6 ГБ датасета) в кэш Hugging Face и читать с диска |
| `SCAN_ROWS` | `300_000` | сколько строк партиции просматривать при чтении по сети; `None` — всю партицию (точнее, но по сети заметно дольше) |
| `MIN_ROW_GROUPS` | `3` | минимум row-групп в просмотре, чтобы выборка не пришла из одного непрерывного куска файла |

Row-группы для просмотра отбираются равномерно по всему файлу, поэтому выборка покрывает всю
партицию, а не её начало. При чтении с локального файла (`RFSD_LOCAL_PATH`) `SCAN_ROWS`
игнорируется и просматривается вся партиция.

## 4. Найденные закономерности, связи и аномалии

**1. Логнормальность и экстремальная концентрация.** Среднее по всем денежным показателям
превышает медиану в разы, коэффициент асимметрии — десятки, коэффициент Джини по выручке ≈ 0.9.
Правило Тьюки помечает выбросами огромную долю наблюдений, но это не брак данных, а естественное
распределение размера фирм: отсекать такие «выбросы» нельзя, нужно логарифмировать. В лог-шкале
распределения выручки и активов становятся почти колоколообразными.

**2. Часть «сильнейших корреляций» — бухгалтерские тождества, а не экономика.** `B_assets` и
`B_liab` имеют r ≈ 1.00, потому что актив и пассив равны по определению; то же для
`1600 = 1100 + 1200` и `1700 = 1300 + 1400 + 1500`. Это одновременно инструмент валидации данных
(нарушение тождества = битая запись) и ловушка: идеальная мультиколлинеарность и утечка целевой
переменной, если строить модель прибыли по всем строкам отчётности.

**3. Обманчивые знаки (неожиданная связь).** Выручка и себестоимость коррелируют **отрицательно**,
хотя экономически связь прямая. Причина: расходные строки российской отчётности (`line_2120`,
`line_2410`, `line_2330`) печатаются в формах в круглых скобках и хранятся в RFSD со знаком
«минус». В ноутбуке это доказывается тождеством: выполняется вариант `2100 = 2110 + 2120`, а не
`2100 = 2110 − 2120`. После разворота знака корреляция становится сильно положительной, а точки в
лог-лог координатах ложатся вдоль биссектрисы.

**4. Масштаб предсказывает масштаб, но не рентабельность.** Выручка и активы связаны степенным
законом — в лог-лог координатах это прямая с высокой корреляцией по логарифмам. С чистой прибылью
связь заметно слабее, причём Пирсон здесь **ниже** Спирмена: линейный коэффициент портят несколько
фирм-гигантов и редкие крупные убытки. Разбивка по децилям выручки уточняет картину: доля убыточных
фирм с ростом размера систематически падает (мелкие уходят в минус в разы чаще крупных), но
медианная рентабельность во всех децилях держится в пределах нескольких процентов, а разброс маржи
внутри дециля в разы больше разницы между децилями. Размер связан с вероятностью убытка, а не
с уровнем маржи.

**5. Главная особенность данных — не выбросы, а неслучайные пропуски.** Заполненность колонок гуляет
от четверти до четырёх пятых: RFSD намеренно включает фирмы, не сдававшие отчётность, а упрощённая
форма содержит меньше строк, чем полная (валовой прибыли в ней нет вовсе). Признак `simplified` при
этом работает как прокси размера — право на упрощённую форму имеют только малые предприятия, и на
диаграмме «активы–выручка» он делит облако на две зоны. Это классический механизм MNAR: заполнять
пропуски нулями или средними без учёта `simplified` и факта сдачи отчётности нельзя, а сама
заполненность строки — полноценный признак для модели.

**6. Аномалии, о которых надо помнить.** Заметная доля фирм с ровно нулевой выручкой и нулевым
балансом (RFSD намеренно включает «спящие» и не сдающие отчётность фирмы), фирмы с отрицательным
собственным капиталом (техническая несостоятельность) и заведомо нереалистичные значения в верхнем
хвосте — сами авторы датасета приводят пример ООО, показавшего 3.7 трлн руб. выручки (≈2% ВВП
России), и предусматривают для таких случаев флаг `outlier`.

## 5. Запуск

```bash
git clone https://github.com/shsv88/rfsd-exploratory-analysis.git
cd rfsd-exploratory-analysis

python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install pandas numpy pyarrow huggingface_hub matplotlib seaborn jupyter

jupyter notebook rfsd_analysis.ipynb
```

Ноутбук работает и в Google Colab: нужен интернет, регистрация на Hugging Face не нужна, файл
партиции не скачивается. Если чтение по сети идёт долго, поставьте `STREAM_OVER_NETWORK = False` —
файл партиции один раз попадёт в кэш и дальше будет читаться с диска. Если parquet уже скачан
вручную (с Hugging Face или [Zenodo](https://doi.org/10.5281/zenodo.14622208)), укажите путь
к файлу:

```bash
export RFSD_LOCAL_PATH=/path/to/RFSD/year=2023/part-0.parquet   # Windows: set RFSD_LOCAL_PATH=...
jupyter notebook rfsd_analysis.ipynb
```

Воспроизводимость обеспечена фиксированным `RANDOM_STATE = 42`.
